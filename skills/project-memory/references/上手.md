# 上手 — 新会话快速接上

目标:读最少的文件,输出 200 字以内的上手简报,然后等用户说要做什么。

## 第 1 层(必读)

1. `PROJECT-STATE.md`;没有它而有旧版 `INDEX.yaml` → 读 INDEX.yaml,并在简报末尾提示"可以说『初始化』升级成 PROJECT-STATE"。
2. `PREFERENCES.md`(有就读)。
3. `DECISIONS.md`、`GOTCHAS.md` 的**索引里标 `[critical]` 的行**。

只读第 1 层就能写简报。

## 第 2 层(按当前任务挑着读)

| 要做的事 | 读什么 |
|---|---|
| 任何任务 | CONTEXT.md 的"概览"和"硬约束" |
| 接着上次干 | 最新 1~2 份 SESSIONS |
| 改结构、选方案 | DECISIONS.md 里相关标签的详条 |
| 写代码、调试 | GOTCHAS.md 里相关标签的详条 |
| 部署、运维 | RUNBOOK.md |
| 拿不准 | CONTEXT.md 全文 + 最新 1 份 SESSIONS |

## 第 3 层(很少需要)

ARCHIVE/、旧 SESSIONS、GOTCHAS 全文搜索——只在查历史、排查老问题时读。

## 简报格式(≤200 字,超了就压缩)

```
## <项目名> — 上手简报
状态:<一句话>
上次(<日期>):<做完的事>;遗留:<问题>
动手前注意:1. <最重要的约束或坑> 2. <第二>
你的偏好:<1~3 条>
建议从这里开始:<第一步>
```

## 顺带检查

STATE 的更新日期超过 7 天,或 SESSIONS 里有超过 30 天未归档的 → 简报末尾加一句"可以说『整理记忆』"。不自动整理。

## 核对

记忆只代表写下那一刻。记忆里提到的文件、函数、命令,动手前先确认还存在;记忆和代码矛盾时以代码为准,并告诉用户哪条记忆过时了。
