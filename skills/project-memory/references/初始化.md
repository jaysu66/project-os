# 初始化 — 给项目建记忆

目标:用最少的问题建出能用的记忆。必建 3 个文件,其余有内容再建。

## 步骤(共 5 步)

1. 看现状:
   - 已有 `.agent-memory/PROJECT-STATE.md` → 告诉用户"已建过",只补缺的文件,不覆盖。
   - 只有旧版 `.agent-memory/INDEX.yaml`(没有 STATE)→ 先问用户:"要不要根据 INDEX.yaml 生成 PROJECT-STATE.md?INDEX.yaml 保留不删。"同意才继续,并在第 2 步加 `--migrate`。
2. 在项目根运行:`node <本 Skill>/scripts/init.cjs`(加 `--no-entry` 可跳过入口指路)。
   它创建缺失的 `PROJECT-STATE.md`、`CONTEXT.md`、`PROTOCOL.md`,并在项目根 `CLAUDE.md`、`AGENTS.md`
   末尾追加一段 ≤5 行的指路(文件不存在就新建;已有这段就跳过)。
3. 收集信息:当前会话里已经知道的先填,只问缺的,一次问完,最多 7 个:
   1. 项目叫什么,一句话做什么?
   2. 怎么跑起来,部署在哪?
   3. 用了哪些关键技术?
   4. 接了哪些外部服务(数据库、API、平台)?
   5. 2~3 个最重要的决定,为什么这样定?
   6. 遇到过最难的问题,怎么解决的?
   7. 还有什么没做完,或下次要注意的?
4. 填文件:
   - 回答 1、2、3、4 → `CONTEXT.md`;一句话和当前状态 → `PROJECT-STATE.md`
   - 回答 5 → 建 `DECISIONS.md`(模板 assets/DECISIONS.template.md)
   - 回答 6 → 建 `GOTCHAS.md`(模板 assets/GOTCHAS.template.md)
   - 回答 7 → STATE 的"待办"
   - 迁移旧版时:INDEX.yaml 的 project/purpose/status → STATE 顶部;pending → 待办;sessions 最近 3 条 → 最近会话
   - 不知道的写 `[待补充]`
5. 更新 STATE 的"文档地图",只列真实存在的文件。汇报:建了什么、跳过了什么、还有哪些 `[待补充]`。

## 不要做

- 不读整个代码库去"自己补全";拿不准就写 `[待补充]`。
- 不删除、不改写已有文件(包括旧版 INDEX.yaml、AGENT_PROTOCOL.md)。
