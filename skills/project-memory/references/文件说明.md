# 每个文件存什么、为什么

设计照着 Claude 的记忆机制:**先读一页再按需读、记用户纠正过什么、只记查不到的**。

| 文件 | 什么时候建 | 存什么 | 为什么 |
|---|---|---|---|
| `PROJECT-STATE.md` | 必建 | 一句话、当前状态、正在做、待办(≤5)、最近会话(3 行)、文档地图;≤60 行 | 唯一入口,10 秒知道该读什么。像 CLAUDE.md + 记忆索引 |
| `CONTEXT.md` | 必建 | 很少变的:项目是什么、谁用、怎么跑、技术栈、外部服务、目录、环境变量名(不写值)、硬约束 | 和常变的 STATE 分开,改得少就不容易过时 |
| `PROTOCOL.md` | 必建 | 开工读什么、收工写什么、何时整理、谁能改什么 | 换哪个 Agent 都按同一套规矩读写 |
| `PREFERENCES.md` | 第一次被纠正时 | 本项目的偏好,每条带日期和出处 | Agent 最该记住的不是项目细节,而是你纠正过它什么 |
| `DECISIONS.md` | 第一个决定时 | 索引一行一条 + 详条:背景、决定、没选的方案和理由、代价、**除非什么情况否则不推翻**、状态 | 防止下一个 Agent 推翻想清楚的决定 |
| `GOTCHAS.md` | 第一个坑时 | 索引 + 详条:现象、根因、解法、涉及文件、可重跑的命令、出现次数 | 同一个坑不踩第二次;踩 3 次升级为硬约束 |
| `RUNBOOK.md` | 有部署流程时 | 本地跑、上线、回滚、常用命令、报错速查 | 运维照抄 |
| `SESSIONS/日期.md` | 每次收工 | 目标、完成、问题和解法、改动的文件、遗留、新发现、偏好信号 | 接着干时只读最新 1~2 份。像 Claude 压缩时的摘要 |
| `ARCHIVE/年-季度.md` | 整理时 | 30 天前的会话,一份一行 | 不删,但不再占读取额度 |
| `COMPACT-SNAPSHOT-<分支>.md` | hook 自动 | 压缩前的时间、最近 5 个提交、未提交改动、分支 | 压缩摘要会丢细节,这份只记客观事实 |

## 三种写法

- **只追加**:DECISIONS、GOTCHAS、PREFERENCES、SESSIONS。推翻 = 新增一条 + 旧条目标"已推翻"。
- **覆盖更新**:PROJECT-STATE、CONTEXT。始终只写"现在的真相"。
- **只读模板**:PROTOCOL(用户可以改,Agent 不改)。

## 旧版兼容

v2 的 `INDEX.yaml`、`AGENT_PROTOCOL.md` 仍可读,不删除。初始化时经用户同意,可以根据 INDEX.yaml 生成 PROJECT-STATE.md。
