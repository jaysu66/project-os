# /os 接入 — 给项目建记忆和协作骨架("帮我记录一下这个项目"也走这里)

目标:用最少的问题建出能用的项目记忆;同时备好多会话协作的骨架。已存在的文件一律不覆盖。

## 步骤(共 6 步)

1. 看现状:
   - 已有 `.agent-memory/PROJECT-STATE.md` → 告诉用户"已接入",只补缺件,不覆盖。
   - 只有旧版 `.agent-memory/INDEX.yaml`(没有 STATE)→ 先问用户:"要不要根据 INDEX.yaml 生成 PROJECT-STATE.md?INDEX.yaml 保留不删。"同意才在第 2 步加 `--migrate`。
2. 在项目根运行:`node <本 Skill>/scripts/init.cjs`(加 `--no-entry` 可跳过入口指路)。它创建缺失的:
   - 记忆:`PROJECT-STATE.md`(含协作段)、`CONTEXT.md`、`PROTOCOL.md`
   - 协作:`MULTI-SESSION-PROTOCOL.md`、`charters/`、`mailbox/BROADCAST.md`、`mailbox/commits/`、`epochs/`
   - 入口:项目根 `CLAUDE.md`、`AGENTS.md` 末尾追加一段 ≤6 行的指路(文件不存在就新建;已有就跳过)
3. 收集信息:当前会话里已经知道的先填,只问缺的,一次问完,最多 7 个:
   1. 项目叫什么,一句话做什么?
   2. 怎么跑起来,部署在哪?
   3. 用了哪些关键技术?
   4. 接了哪些外部服务(数据库、API、平台)?
   5. 2~3 个最重要的决定,为什么这样定?
   6. 遇到过最难的问题,怎么解决的?
   7. 还有什么没做完,或下次要注意的?
4. 填文件:
   - 回答 1~4 → `CONTEXT.md`;一句话和当前状态 → `PROJECT-STATE.md`
   - 回答 5 → 建 `DECISIONS.md`(模板 assets/DECISIONS.template.md)
   - 回答 6 → 建 `GOTCHAS.md`(模板 assets/GOTCHAS.template.md)
   - 回答 7 → STATE 的"待办"
   - 迁移旧版时:INDEX.yaml 的 project/purpose/status → STATE 顶部;pending → 待办;sessions 最近 3 条 → 最近会话
   - 不知道的写 `[待补充]`;协作段只开一个会话时可以不填
5. 锚定(多 worktree 项目才需要):`git rev-parse --path-format=absolute --git-common-dir` →
   在该目录写 `project-os.json`:`{"ssotDir": "<本 .agent-memory 绝对路径>"}`。非 git 项目跳过。
6. hook(可选,默认不装):告诉用户"想自动的话,把 README『Hook』一节的配置粘进 Claude Code 的 settings.json"。
   三个 hook:PreCompact → `scripts/precompact-snapshot.cjs`(压缩前快照);SessionStart → `scripts/sessionstart-nav.cjs`
   (新开、恢复、压缩后自动注入入口);Stop → `scripts/stop-remind.cjs`(有新改动没记时提醒收工)。用户明确要求时才代为写入 settings.json,写之前先备份并给用户看改动。
   脚本自辨:找不到 `.agent-memory` → 静默退出。

完成后输出:建了什么、跳过什么、还有哪些 `[待补充]`、下一步(通常 = 直接干活,收工时说"收工")。

## 不要做

- 不读整个代码库去"自己补全";拿不准就写 `[待补充]`。
- 不删除、不改写已有文件(包括旧版 INDEX.yaml、AGENT_PROTOCOL.md、已有的 CLAUDE.md/AGENTS.md 内容)。
