# /os 收工 — 把这次会话记下来

目标:下一个会话不用问你就能接着干。只记 git 记不住的东西。

## 步骤(共 5 步)

1. 写会话日志 `SESSIONS/YYYY-MM-DD.md`(模板 assets/SESSION.template.md)。
   同一天第二次收工 → 在同一文件追加 `## 会话 2`。多个会话并行、且在某个方向上干活 → 文件名用 `YYYY-MM-DD-<方向>.md`,防止多个会话写同一个文件。
2. 更新 `PROJECT-STATE.md`:当前状态、正在做、待办(≤5 条)、最近会话(最新放最上,只留 3 行)、更新日期。
   多会话时 STATE 只有主 agent 改:非主 agent 跳过这一步,改为写 commit 信。
3. 有新决定 → 追加到 `DECISIONS.md`(先加索引行,再加详条);推翻旧决定 → 追加新条目,旧条目状态改"已推翻(被 D-xxx 取代)"。
4. 踩了新坑 → 追加到 `GOTCHAS.md`;同一个坑再次出现 → 不新建,把原条目"出现次数"加 1 并补一行日期。
5. 扫一遍本次对话里用户的纠正和偏好,追加到 `PREFERENCES.md`(不存在就按模板建):
   - 信号:"不要这样"、"换一种"、"不是这样"、"我更喜欢"、"以后都这样"、"记住这个"、"用 A 不用 B"
   - 每条写清:偏好是什么、日期、出处(哪次会话因为什么说的)
   - 只对本项目有效的才写这里;跨项目的偏好交给宿主记忆

最后一句话告诉用户记了哪几个文件。

## 不记什么

- 改了哪几行代码、提交历史(git 有)
- 只和这一次对话有关、以后用不上的过程
- 没有出处的推测
