# /os 启动 — 会话归位(每会话第一动作)

目标:让本会话理解项目现状,输出固定 12 行报告,**不执行任何实质工作**,等用户验收后才接需求。

## 步骤(严格照做,共 5 步)

1. 定位 SSOT(见 SKILL.md 第 0 步,锚定优先)。记下命中方式(锚定/cwd 兜底)和是否发现分叉副本。
2. Read `<SSOT>/PROJECT-STATE.md`(单页);若存在 `<SSOT>/PREFERENCES.md`(project-memory 的用户偏好)也读。若存在 `<SSOT>/mailbox/BROADCAST.md`,只读**末尾 3 条**(os v2 起新条目真追加在文件末尾)。
3. 自检三项:①`<SSOT>/locks/` 有无 `主线.lock.md`(有→记下谁/何时/干什么;超 24h 视为疑似遗弃)②若项目配置了 AGENTS.md/CLAUDE.md 等入口,比对其中协议版本与 STATE;未配置则记为未配置 ③**代码新鲜度**:非主线 worktree 时跑 `git rev-list --count HEAD..<主线分支>`(主线分支名见 STATE),>0 = 本分支落后主线 N 个 commit。
4. 判断自己身份:用户此前明示过"主 agent/总负责人" → 主 agent(额外负责打包/发版/收割汇总/维护 STATE);否则为**项目负责人**——在自己认领的 worktree 干活,commit 后写 commit 信到 `mailbox/commits/<方向名>.md` 同步主 agent。
5. 输出以下固定格式,然后停(不要接着做任何事):

```
📍 归位报告
- 项目:<STATE 第一节一句话>
- 线上/当前版本:<STATE 里的版本行>
- 我的身份:主 agent / 项目负责人(写权见锁;commit 后发 commit 信)
- SSOT 自检:锚定命中(<路径>)/ cwd 兜底 / ⚠️发现分叉副本 <路径>
- 主线锁:空闲 / 被 <谁> 持有(<何时>,<干什么>)/ ⚠️疑似遗弃(>24h)
- 协议:项目入口协议 v<N> vs STATE 期望 v<M> —— 一致 / ⚠️未配置或版本不一致
- 代码:主线 worktree / 与主线同步 / ⚠️落后主线 N commit(建议先合主线再迭代)
- 并行中方向:<STATE 方向表的名字列表>
- 广播:<最新 1 条摘要 / 无未读>
- 信箱:<有无发给本会话身份的 REQUEST / 未知(尚未认领方向)>
- 矩阵:<STATE 矩阵归属行的产品名;若 STATE 无此行则省略本行>(全景 /os 矩阵)
- 依据:PROJECT-STATE.md(更新于 <日期>)
已归位,请说需求。
```

## 归位后接需求的规则

- 用户需求命中某 charter(STATE 方向表里有)→ Read 该 charter,复述"我认领 <名>,边界是 …",确认后干活。**干活前若报告显示落后主线 → 先 `git merge <主线分支>`(冲突当场解决),保证在最新代码上迭代。**
- **需求要改主线代码** → 先看主线锁:空闲 → 写 `<SSOT>/locks/主线.lock.md`(本会话身份/日期时间/一句话在干什么)认领,收工删除;被占 → 提示用户"主线被 <谁> 持有,建议开方向 worktree 或明示抢锁(抢锁=覆写锁文件并在广播留一句)"。
- 需求不属于任何 charter → 提示"这像新方向,要 /os 开方向 吗?"或按普通任务处理(commit 后照发 commit 信)。
- 压缩恢复后:先读 PROJECT-STATE.md + 本分支的 `COMPACT-SNAPSHOT-<分支>.md`;**改任何文件前重新 Read 一遍目标文件**(可能有并发改动)。
- 若发现 STATE 与 git/代码现实矛盾 → 以代码为准,提醒用户并(主会话)顺手修 STATE。

## 省 token 红线

只读 STATE + 广播末尾 3 条 + (认领后的)一份 charter;不读 DECISIONS/GOTCHAS/历史,除非任务需要。
