# /os 接入 — 新项目初始化 project-os

目标:在当前项目建立整套体系(SSOT 骨架 + 锚定 + 双 agent 入口 + hook),一次到位。

## 步骤(共 6 步)

1. 幂等检查:已有 `.agent-memory/PROJECT-STATE.md` → 提示"已接入",只补缺件,不覆盖。
2. 跑骨架脚本:`node <skill>/scripts/init.cjs`(在项目根执行)。它创建:
   `.agent-memory/{PROJECT-STATE.md, MULTI-SESSION-PROTOCOL.md, charters/, mailbox/BROADCAST.md, mailbox/commits/, epochs/}`
   (模板来自 skill assets;已存在的文件一律跳过)。
3. 采访用户填 STATE 首版(≤60 行):项目一句话 / 当前版本与状态 / 主仓库路径与分支 / 铁律(如有)。
4. 锚定(多 worktree 项目):`git rev-parse --path-format=absolute --git-common-dir` →
   在该目录写 `project-os.json`:`{"ssotDir": "<本 .agent-memory 绝对路径>"}`。非 git 项目跳过。
5. 双 agent 入口:项目根 `CLAUDE.md` 与 `AGENTS.md` 各追加(不覆盖既有内容)同一段 ≤8 行协议:
   ```
   ## project-os 会话协议
   1. 本项目 SSOT = .agent-memory/PROJECT-STATE.md。
   2. 会话第一响应 = 归位报告(格式见本 Skill 的 `references/启动.md`),不做实质工作,等用户确认。
   3. 每个会话都是项目负责人:主线可改、可 commit;每次 commit 后写 commit 信到
      .agent-memory/mailbox/commits/<方向名>.md(改动点+用户关键决策+设计原因)同步主 agent。
      打包/发版/收割汇总/维护 STATE 只归主 agent(用户明示)。
   4. 需求命中 charters/ 里的方向就认领它;结束前在该 charter 进展日志追加一行。
   ```
6. hook(可选):宿主若支持生命周期 hook,由用户自行把
   `node "<skill绝对路径>/scripts/precompact-snapshot.cjs"` 接到 PreCompact；本 Skill 不修改
   全局设置。脚本自辨:cwd 无 `.agent-memory` 且锚定也找不到 → 静默退出。

完成后输出:建了什么、跳过什么、用户下一步(通常=「/os 开方向」或直接干活)。
