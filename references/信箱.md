# /os 信箱 — 会话间传话(收/发/裁决)

目标:会话之间用文件传话(沿用 session-handoff 的 REQUEST→DISCUSSION→归档协议),用户只当"门铃"。

## 目录约定

`<SSOT>/mailbox/<发方>--to--<收方>/`,身份 = charter 名(主 agent = main)。
每个信箱目录里:`REQUEST.md`(发起)/ `DISCUSSION.md`(应答/反提)/ `HANDOFF_LOG.md`(归档)。
另有 `mailbox/commits/<方向名>.md` = 各负责人的 commit 信(追加式,专发 main,不走 REQUEST 协议)。

## 收信步骤(用户说"查信箱")

1. 确定本会话身份(main 或已认领的 charter 名)。
2. Glob `mailbox/*--to--<本身份>/REQUEST.md`,逐封读(通常 0-2 封,很短)。
3. 对每封:能直接答/办 → 写 `DISCUSSION.md`(同意/结果/反提);涉打包/发版/STATE 汇总且自己非 main → 回"由主 agent 处理"。
   自己是 main → 顺手把 `mailbox/commits/` 里未读的 commit 信过一遍(收割时正式汇总)。
4. 办结的:双方内容摘要一行进 `HANDOFF_LOG.md`,删 REQUEST/DISCUSSION 正文(留 LOG)。
5. 向用户汇报:每封一行(谁、要什么、我怎么答的)。

## 发信步骤(用户说"发消息给 X:内容")

1. 写 `mailbox/<本身份>--to--<X>/REQUEST.md`:背景 2 行 + 请求 1-3 条 + 期望产物/格式。
2. 提醒用户:"已写入,请到 <X> 会话说一声『/os 信箱』"。

## 裁决规则(main 专属)

涉打包/发版/端口分配/STATE 汇总的请求只有 main 能批;批了就按请求执行或排期,答复写 DISCUSSION。
(主线代码人人可改,不需批;交叠冲突时 main 出面协调优先级。)
