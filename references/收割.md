# /os 收割 — 阶段收口(仅主 agent)

目标:把各方向的进展收进 PROJECT-STATE,验收产出,保持 SSOT 鲜活(防荒废)。

## 步骤(共 7 步)

1. 身份检查:本会话不是主 agent → 拒绝,提示"收割是主 agent 动作,可 /os 接管"。
2. **读 `mailbox/commits/*.md` 未收割条目**(各负责人的 commit 信:改动点/用户决策/设计原因)——这是收割的主料;汇总后把条目移入各文件底部「已收割」小节。
3. 遍历 `<SSOT>/charters/*.md`,只读每份的「进展日志」末尾 3 行(省 token)。
4. 查 `mailbox/`:有无未归档的 REQUEST(挂起的跨会话请求)→ 列出待裁决。
5. 有交付物的方向:按其 charter「产出约定」验收(存在性+抽查),该集成的集成,该打包的打包。
6. 更新 `PROJECT-STATE.md`:方向表状态列、版本行、日期。**保持单页(≤60 行),挤出去的细节进专题文档。**
7. 输出收割摘要(每方向一行:名 / 新进展一句 / 待用户决策项)。

## stale 检查(顺手做)

- STATE 更新日期距今 >7 天 → 本次必须刷新日期并提醒用户"上次收割是 X 天前"。
- 某 charter >14 天无日志 → 在摘要里标"⚠ 疑似停滞",问用户是续、是停、是并入别的方向。

## 铁律

- 收割不启动新工作,只汇总/验收/登记;新活等用户点。
- DECISIONS/GOTCHAS 有新条目才追加,一条一行,带日期。
