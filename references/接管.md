# /os 接管 — 接任主 agent(封号/换工具/换机/前主 agent 丢失时)

目标:新会话安全接任"主 agent"(打包/发版/收割汇总/维护 STATE 的职责),不裂脑、不丢前任半成品。

## 步骤(共 6 步)

1. 定位 SSOT(锚定优先),Read `PROJECT-STATE.md` + 主线分支的 `COMPACT-SNAPSHOT-<分支>.md`(若在;旧版单文件 `COMPACT-SNAPSHOT.md` 只作参考,可能混有别的 worktree 状态)。
2. 查前任遗留:在主线仓库跑 `git status --short` + `git log --oneline -5`。
   有未提交改动 → 逐条列出,标注"前任半成品,接管后需处置"。
3. Read STATE 里「主 agent 登记」行:若登记的主 agent 仍可能活着(用户没说它死了)→ 提醒用户
   "同时只能有一个主 agent,确认旧主已废弃?" 等确认。同时扫 `mailbox/commits/` 未汇总的 commit 信,列给用户。
4. 输出接管报告:
```
🔑 接管报告
- 接管人:<本 agent/模型名>,自 <今日日期>
- 项目现状:<一句话> / 版本 <x>
- 前任遗留:<N 处未提交改动(列表)/ 干净>
- 待办快照:<COMPACT-SNAPSHOT 或 STATE 里的进行中事项>
风险已列明,确认接管请回复"确认"。
```
5. 用户确认后:更新 STATE 的「主 agent 登记」行(谁、自何日);接管即持有主线写权 → 覆写 `<SSOT>/locks/主线.lock.md`(本会话/日期/接管);`/os 广播` 一条"主 agent 已由 X 接管"。
6. 此后本会话为主 agent,按主 agent 职责行事(收割/集成/打包/发版/维护 STATE)。

## 注意

- 本流程对任何 agent 通用(Claude/codex/grok):SSOT 全是 markdown,主 agent 不绑定供应商。
- 更换 Agent 宿主时，项目事实仍以仓库中的 SSOT 为准；宿主全局记忆是否迁移由宿主自行负责。
